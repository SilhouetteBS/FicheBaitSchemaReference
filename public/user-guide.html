FICHEBAIT SCHEMA REFERENCE

Explore a schema with its version and evidence in view

Browse exported database metadata, trace relationships, compare snapshots, and find reporting guidance for Laserfiche products.

Guide checked against the interface on October 21, 2026. Screenshots use a Forms snapshot as an example; versions, object counts, and documentation coverage can change.

How it works

Schema Reference reads versioned exports of SQL Server metadata and published research notes. It does not connect to your databases, read customer rows, or execute SQL. Select a product and exact version to browse tables, views, routines, triggers, keys, indexes, and relationships available in that export. Database names vary by installation and do not identify a product or build.

Structural facts come from exported metadata. Column purposes, status meanings, and reporting guidance have separate evidence and confidence labels. A foreign key establishes a constraint; a dependency establishes an expression reference, not a verified join. Missing metadata or an empty table in a test environment does not establish that a feature is unused.

In Compare, structural object changes appear by default. Definition-only changes mean fingerprints differ, not that a functional or breaking change has been established. Expand Technical details for the fingerprints; the exports do not include SQL definition text for a line-by-line diff.

Use Help in the header for this guide, About, or Feature Requests. Corrections remain beside the relevant reference content. About opens without replacing your search or selection. Use the guide's Open Schema Reference links to return to your previous view.

Diagram connections and objects

  • Foreign key: exported column-to-column constraint.
  • Dependency: SQL expression reference, not necessarily a join.
  • Direct focused relationship: connection directly involving the focused object. Selected relationships also use the highlight color.
  • Trigger parent: the object to which a trigger belongs.
  • Table: stored rows and columns.
  • View: named query.
  • Routine: stored procedure or function.
  • Trigger: event-driven SQL object.

High-contrast mode may change diagram colors and patterns; labels still identify the relationship type.

Choose a snapshot

  1. Open schema.fichebait.com. If prompted, sign in with the account granted access.
  2. Use Product in the left navigation to choose Forms, LFDS, Repository, or Workflow from the available catalog.
  3. Select the exact Version you want to inspect. The choices are exported snapshots, not a connection to your installed server.
  4. Check the product/version heading and Exported date. Expand Metadata details for the snapshot’s available provenance and completeness details.
  5. Choose Tables, Diagram, Compare, or Reporting. Expand Schema tools for the other views.

The reference is an independent database schema reference for read-only reporting, troubleshooting, and education. Reading it does not connect to your databases or execute SQL. Direct modification of Laserfiche product databases is unsupported. Read the expandable notice and the guidance attached to each object or script.

Choose the matching build whenever available. A nearby snapshot can help research a question, but it does not establish that the same objects or behavior exist in your environment.

Worked example: trace a Forms instance to its process

Question: “Which exported key connects a Forms main instance to its process?” This exercise uses the Forms 12.0.2607.40144 snapshot as an example. It does not query a customer database or run SQL.

  1. Select Product: Forms and Version: 12.0.2607.40144. Check Exported and Metadata details. The example metadata records exportedAtUtc as 2026-10-09T21:30:36. Keep that UTC export context with saved files.
  2. Open Tables, search for cf_bp_main_instances, and select dbo.cf_bp_main_instances. Read the purpose/confidence and warnings before interpreting the names.
  3. Open Columns and find process_id. The example export defines it as non-null int. That is a structural fact for this snapshot, not a complete explanation of the process lifecycle.
  4. Open Relationships and inspect the outgoing foreign key FK_bp_main_insts_bp_process: dbo.cf_bp_main_instances.process_id references dbo.cf_bp_processes.process_id. Follow the linked target table and inspect its key/column metadata.
  5. For a visual check, open Diagram, choose Focused neighborhood, select dbo.cf_bp_main_instances, and set Relationships to Foreign keys. Use Fit selection or the zoom controls to inspect the link. A dependency line from another view would not establish the same column mapping.
  6. Return to the selected main-instance table and choose Relationships CSV or Download table JSON. Record the exact product/snapshot and exported timestamp with the file. Use Copy current view link to preserve the supported selection context.

Expected result: a saved reference file and note identifying the source column, target column, foreign-key name, and snapshot. For example:

Forms 12.0.2607.40144, UTC export timestamp 2026-10-09T21:30:36: FK_bp_main_insts_bp_process maps dbo.cf_bp_main_instances.process_id to dbo.cf_bp_processes.process_id. This establishes the exported relationship. Report row counts, business filters, permissions, performance, and compatibility with the installed build still require separate validation. No SQL was executed.

If the object or relationship is missing in another snapshot, clear filters and review metadata completeness. Do not substitute a same-name column or dependency as proof of a foreign key. Continue with reporting guidance only when you need to evaluate a candidate script.

Useful terms and safe first steps

Snapshot
Exported metadata for a selected product/version, with its own export date and coverage.
Foreign key
An exported constraint mapping specific source columns to referenced columns.
Dependency
An expression reference between objects; it is not automatically a join or verified business relationship.
Inferred / Unknown
Explanations that are not confirmed, or meanings not yet established. Preserve these labels in research notes.
Export
A reference file for the selected scope, not customer row data or a database backup.

Start by selecting the exact snapshot, checking the metadata, and saving the relationship evidence. Use the application’s full Glossary, Export compatibility, and Caution notes when evaluating broader reporting assumptions.

Find and read a table

  1. Select Tables.
  2. Use Search tables, columns, descriptions to find a table by name, column, or documented purpose. A search can return related tables because a matching term appears in their notes.
  3. Optionally narrow Confidence and Notes. Clear the search and return both filters to their all-values options to broaden the list.
  4. Select a table. Read its purpose, confidence label, read-only guidance, and warnings.
  5. Use the detail tabs below to inspect the part you need.
Table sectionWhat to inspect
ColumnsNames, types, nullability, purpose, lifecycle information, and review status. Use Find column within the selected table, and Density to choose Comfortable or Compact.
Keys / IndexesExported key and index definitions. A name or index alone does not explain the business meaning of a column.
RelationshipsIncoming and outgoing relationships and their available details. Follow a linked table to inspect the other side.
ScriptsReporting patterns associated with the table. Open a script to read its SQL, review notes, and resources.
NotesPublished manual notes, review context, and sources where provided.

The Stability, Related, and Trend controls above the tabs provide reporting context. History can load on demand; an unloaded history panel is not a finding that the table never changed.

Use the star beside an object to pin it for easier return in this browser. Pins and view preferences are browser-local conveniences, not shared documentation edits.

Read confidence and metadata correctly

Exported structural metadata and explanatory notes answer different questions. The snapshot can establish that a column or foreign key was exported while its business purpose remains inferred.

LabelHow to read it
UnknownThe meaning or guidance has not been established.
InferredThe explanation is an inference; seek supporting evidence before relying on it.
ObservedThe note reflects observed evidence in its documented context.
ConfirmedThe note has a higher review level; retain its source and version scope.
Deprecated / Do not relyRead the attached warning or review note before using the information.

A Manual notes badge means explanatory notes exist. It does not mean every column is confirmed. The documentation coverage counts describe note coverage, not database health or live testing. “Current” or historical lifecycle information is relative to available snapshots.

Explore the diagram

  1. Select Diagram.
  2. Use Find object to narrow the object choices, then select an item in Object.
  3. Choose Focused to explore the selected object’s neighborhood, or Full database for the broader map.
  4. Set Relationships to All, Foreign keys, Dependencies, or Trigger parents. Read the legend to distinguish line types.
  5. Select a visible object or relationship to inspect its context. Use the viewport controls and Zoom to make the map readable.

Foreign keys represent exported SQL constraints between table columns. Dependencies represent SQL expression references from objects such as views, routines, or triggers. A dependency is not automatically a valid join path or proof of business meaning.

  • Fit diagram, Fit selection, Center focus, and the pan controls help reposition the map. Center focus requires a selected object.
  • Options contains display and object-type controls such as edge labels, compact cards, curved lines, and high contrast. Some controls depend on the current mode.
  • Path finder compares the selected From and To objects among visible objects and relationships. A missing path can reflect filters or incomplete exported metadata.
  • Presets lets you save the current view and apply a saved preset in this browser.
  • Export offers Viewport PNG, Full diagram SVG, and Selected relationship JSON. The relationship export needs a selected relationship.
  • Reset view and Reset filters address different things: use the relevant control when the map is off-screen or filtered too narrowly.

Compare versions

  1. Choose the product, then select Compare.
  2. Select a baseline in From and a target snapshot in To.
  3. Read the added, removed, changed, and unchanged counts and the What changed summary.
  4. Under Changed tables, use All, Columns, Keys, Indexes, or Relationships to narrow the change list. Use Breaking only when you want the tool’s flagged changes.
  5. Select Details beside a changed table to inspect its differences. Select the table name to open its table documentation.
  6. Use JSON or CSV in the comparison header to export the comparison.

High, medium, low, and breaking-change labels help prioritize review. They are not a live assessment of your reports or integrations. Check the actual type, key, index, and relationship changes against the query or application you maintain.

Use reporting guidance

  1. Select Reporting for the chosen product and version.
  2. Start with Common questions or Common paths, inspect Generated examples, or use Find scripts to locate a reporting pattern.
  3. Select a curated script or an available object-name-matched candidate.
  4. Read the applicability text and labels, then switch among SQL, Review notes, and Links to Resources.
  5. Follow table links to check the referenced metadata. Use Copy SQL only after the SQL has loaded and you have reviewed its requirements.

Object names matched means referenced names were matched against documented schema metadata. It does not validate every column, join, result, execution plan, or installed build. Not live tested, Needs review, Schema neutral, and Context only labels retain those limits.

Generated examples are starting points. Some curated scripts create views or procedures in a separate reporting database while reading product metadata. Read the intended deployment location and permissions before using them. The reference displays and copies SQL; it does not run or deploy it. Review and validate any chosen script through your normal test and support process.

Use Glossary, Export compatibility, and Caution notes for terminology and interpretation limits.

Before using SQL outside the reference

Reading, exporting, or copying here grants no database permissions. A database administrator must review the candidate’s target database, referenced objects, data access, deployment statements, and execution plan through the normal test process. Use an approved read-only identity for product-data reads. Scripts that create reporting views or procedures require separately approved DDL permissions in the intended reporting database; do not deploy them into a Laserfiche product database. Object-name matching alone does not validate column semantics, joins, performance, security, or results.

Export and share your context

Use Copy current view link in the top bar to copy a link retaining supported product, snapshot, view, and selection context. Paste it into your notes or ticket. If copying fails, copy the browser address. A link does not grant access; recipients need their own permitted access.

Export controls apply to their own scope:

  • The product/version panel’s Markdown exports a snapshot summary.
  • A selected table offers Download table JSON, Columns CSV, Relationships CSV, and Markdown.
  • Export unknown CSV saves a documentation-gap list, rather than the selected table’s column export.
  • Compare, Diagram, and the schema tools provide their own report or image exports.

Keep product and exact snapshot with saved files. Exports represent the reference’s metadata and notes; they are not a backup or an export of customer row data.

Navigate quickly

Select Command, or press Ctrl/Command + K, to search views, tables, columns, objects, and relationships in the selected snapshot. Choose a result to navigate. Help > Keyboard shortcuts or ? shows the available shortcuts. Number keys switch views when you are not typing in a field. In Diagram, +/− adjusts zoom, F resets zoom, and Escape clears focused diagram state.

Explore schema tools

Expand Schema tools in the left navigation.

ToolSteps and interpretation
ObjectsChoose views, routines, triggers, or dependencies; select an object to read its exported details. Use Column usage search to find a named column across tables. The documentation review queue identifies notes needing attention; Export queue downloads that queue.
ImpactReview the ranked table list, then select a table to inspect it. Ranking uses metadata such as relationships, dependencies, indexes, and note coverage; it is a documentation priority, not a measured production-impact score. Export impact saves the report.
Schema checksReview the documentation queue, structural flags, and unresolved dependency drilldown. Select a table row to inspect its metadata. These checks assess the snapshot and its documentation, not your running server.
DependenciesRead the dependency totals and unresolved rows, including Referencing, Referenced, Flags, Likely reason, and Suggested fix. Export dependencies downloads the report.

An unresolved dependency can involve an alias, pseudo table, check constraint, caller-dependent name, or object absent from the export. It is a completeness warning, not proof that a database is invalid. A suggested fix in this report concerns metadata review and resolution; it is not an instruction to alter a product database.

Troubleshooting and support

A table, column, or object is missing

Confirm the product and exact version. Clear table search and confidence/notes filters. Check Objects for views, routines, and triggers. A missing export or incomplete note is not proof that the object is absent from your installed database.

The diagram is empty or incomplete

In Focused mode, choose an object first. Check Relationships and Options for excluded types or filters, then try Fit diagram or Reset filters. Review Dependencies for unresolved references. Different line types describe different metadata; do not infer a join from a matching name alone.

Two versions show unexpected differences

Check From and To, export dates, and Metadata details. Export coverage can differ between snapshots. Review the actual change details before classifying a report as affected.

A source or script cannot load

Retry the view and check access to external resources separately. Include the current view URL and exact message in a support ticket. Do not treat an unloaded section as an empty schema or a validated script.

Report a correction or request help

Select Report correction to open a GitHub issue form with the current product, version, area, and object context. Review the fields, explain the correction, and add non-sensitive source evidence before submitting on GitHub. Opening the form does not submit it.

For private assistance, submit a support ticket with the view URL, product, exact snapshot and installed build, object name, observed problem, and steps already tried. Remove credentials, customer row data, and private server or database details from public corrections.
